## Requirement gap narrowed locally

Audit 14 proved exact signed Keycloak delivery and old-cookie denial through one actual Next.js
process. The authenticated Redis exercise separately proved cross-client revocation and replay, but
neither result exercised two actual web replicas or a dependency outage. The remaining bounded local
topology gap is now materially narrower:

- two processes use a fresh optimized Next.js production build and start with `next start`,
  `NODE_ENV=production`, fatal Node deprecations, one session secret, one OIDC client/issuer, and
  `SESSION_REVOCATION_STORE=redis`;
- an ephemeral loopback TLS proxy routes the canonical application origin across both processes,
  while two fixed probe origins address each replica without changing cookie or callback authority;
- two isolated browser contexts establish distinct `sid` values for one synthetic Keycloak subject,
  and both encrypted cookies initially work through both replicas without exposing provider
  credentials;
- CSRF-safe RP logout produces one fixed-client/fixed-return provider request, and Keycloak delivers
  one signed Logout Token to replica one;
- the targeted old cookie is rejected through both replicas, the other same-subject `sid` remains
  valid through both, and replay through replica two returns the standard success status;
- only one `sid` and one replay key exist, both use 64-hex HMAC indexes, both have positive TTLs,
  and no raw subject, session ID, or JWT ID appears in a key;
- Redis is stopped with `SIGKILL` after an explicit snapshot. Both replicas fail the unaffected
  authenticated cookie closed, anonymous application liveness remains `200`, and a valid replayed
  logout returns `400` rather than false success;
- the same authenticated persistent Redis authority restarts. The targeted cutoff and replay marker
  remain effective, the unaffected cookie recovers on both replicas, replay is still idempotent, and
  a later provider login works through both replicas; and
- all browser, application, provider, relay, and Redis listeners close after the run.

The verifier holds the encrypted cookies, provider credentials, signed Logout Token, raw
identifiers, Redis keys/credential, OIDC client secret, and synthetic password only in process
