## Requirement gap closed locally

The PRD requires investigations to show source and normalized values side by side, with provenance,
applied rules, tolerance, confidence, and conflict. The API and BFF previously admitted named
evidence, record references, and normalized records as generic JSON. The UI then rendered portions
without a single strict semantic contract.

The completed boundary is:

- the reconciliation engine validates every current evidence object through a strict bounded
  `RuleEvidenceSchema`, including comparison cardinality, record/version/hash identity, integer
  tolerance, candidate-search counts, and distinct 500-entry accounting-candidate and 50-entry
  accounting-split overflow modes;
- the API emits only a discriminated `deterministic-evidence-view-v1` with paired source/normalized
  comparisons, rule/rule-set/result/reason, count/truncation, tolerance, search summaries, and
  evaluation time, or the fixed `EVIDENCE_UNSUPPORTED_OR_MALFORMED` unavailable view;
- unknown, future, legacy, malformed, oversized, or inconsistent evidence produces no raw or partial
  browser evidence;
- canonical records use a closed kind-specific normalized projection. Organization IDs, source-event
  IDs, raw-object provenance, and source-value references are omitted;
- field lineage is all-or-nothing per record after tenant, provider, record-kind, version, hash,
  metadata, field, and location validation;
- exception record references reach the browser only if a bounded unique UUID set exactly equals the
  tenant-resolved source-record set. Malformed, duplicate, unresolved, or cross-tenant references
  become an empty unavailable projection;
- canonical and provenance reads repeat explicit organization predicates inside the existing
  forced-RLS transaction, while the BFF independently validates and reconstructs the same strict
  typed view;
- the operator interface renders structured rule summaries, side-by-side comparison tables, safe
  normalized fields, lineage tables, and explicit unavailable warnings without generic JSON evidence
  rendering.

No migration or reconciliation rule-version change was required. No money, currency, tolerance,
confidence classification, exception decision, approval authority, source-system write, provider
scope, AI authority, or autonomous financial action changed.
