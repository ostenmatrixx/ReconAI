## Representative load boundary

Scenario version 1.0.0 deterministically constructs:

- 20,000 exact order/payment/fee groups;
- 8,000 Shopify/Stripe/accounting refund triples;
- 4,000 paid orders missing payments;
- 4,000 unmatched payment/fee pairs; and
- 4,000 malformed-identifier orders.

That produces exactly 100,000 records: 28,000 orders, 24,000 payments, 24,000 processing fees,
16,000 refunds, and 8,000 accounting entries. The declared result is 36,000 matches, 12,000
exceptions, and zero ambiguous candidates. Each of five fresh Node processes received the same fixed
policy with canonical, reversed, one-third rotated, two-thirds rotated, or canonical-repeat input.

Every process returned:

- engine 0.7.0 and rule set 1.5.0;
- input snapshot `4a97303916eb03e228b9058fbaa06010986b775b93a6926c9eeb9cec56610609`;
- run key `7214740d3f9b436ca03359dec2cbe0a92b39e025a14ce08eda697a12ea92d4ad`;
- complete result digest `1861bc87300a50219b07e5b2f2ffbe19fc5269051cc41937df58b8fa1b68decb`;
- 20,000 order/payment, 8,000 refund, and 8,000 refund/accounting matches; and
- 4,000 each malformed-identifier, paid-order-missing-payment, and payment-missing-order exceptions.

Matched order and payment totals were both 299,990,000 USD minor units. Shopify refund, Stripe
refund, and accounting refund totals were each 21,996,000 USD minor units. No floating-point money
or currency conversion was used.

## Measurements and interpretation

The post-lint source-bound run observed pure-engine durations of 1,664.48, 1,674.15, 1,677.02,
1,688.23, and 1,948.55 ms. Nearest-rank p50 was 1,677.02 ms; nearest-rank p95 was the five-sample
maximum 1,948.55 ms. Maximum observed process RSS was 521,650,176 bytes on the recorded local Apple
ARM64 host.

Five samples are too few for a statistically reliable service percentile. The duration begins only
after deterministic dataset construction and ends when synchronous `reconcile` returns. It excludes
API admission, PostgreSQL snapshot loading, outbox, Redis, worker startup, result persistence,
browser visibility, network time, sustained arrivals, concurrent tenants, and failure recovery. The
proposed ten-minute p95 for the complete 100,000-record job remains an unverified target.

The memory observation is a concrete container/concurrency planning input. It is not proof of a
leak, a production limit, or safe concurrent-worker density.
