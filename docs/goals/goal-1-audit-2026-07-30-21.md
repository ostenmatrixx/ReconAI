## Requirement gap narrowed locally

ADR 0024 deliberately does not promise a snapshot across separately authorized, name-ordered page
requests. A concurrent rename can move an unseen row behind a previously issued cursor, and a row
already seen can move forward and appear again. The security and correctness contract is instead:
every page and exact lookup recomputes current identity authority; deactivated/foreign memberships
remain excluded; browser accumulation deduplicates by organization ID; and search or reload recovers
navigation drift.

Fresh executable coverage now proves that contract:

- all 55 migrations apply to a fresh data-checksummed PostgreSQL 17.10 database through the
  migration role;
- the restricted application role reads the first authorized page for the synthetic identity;
- between requests, a test-harness administrator renames the unseen second tenant from
  `Integration Tenant B` to `Aardvark Concurrent Tenant`, moving it behind the first page's cursor;
- the next page is empty, explicitly proving the documented non-snapshot behavior rather than making
  a false completeness claim;
- exact lookup by that tenant's UUID still returns one currently authorized row with the current
  renamed value;
- fixture deactivation between page requests makes both the next page and exact lookup omit the
  tenant immediately. Reactivation restores one exact reviewer row;
- terminal assertions restore the tenant name and active membership, return zero rows for a foreign
  identity's exact lookup, and return zero organization rows through a tenantless application-role
  table read; and
- a Chromium regression receives the same organization ID on two mutable pages with an updated name.
  The switcher retains two unique organizations, replaces the stale name, and reports no
  automatically detectable accessibility violation.

The fixture changes are direct test-harness controls and are restored before terminal assertions.
They do not claim to exercise the product membership-administration API or its append-only audit
workflow. Existing lifecycle evidence separately covers audited role/status changes through the
application.
