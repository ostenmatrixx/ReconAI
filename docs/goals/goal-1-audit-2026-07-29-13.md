## Requirement gap closed locally

The previous audit left `SEC-L-003` open because NextAuth's transitive `openid-client@5.7.1` used
Node's deprecated, non-standardized `url.parse()` in authentication URL handling. An isolated real
Keycloak flow had emitted `DEP0169`. Replacing the authentication framework at that point would also
replace proven refresh, encrypted-session, logout, revocation, BFF, and API-verification behavior.

The completed boundary is:

- pnpm binds the exact transitive package to a checked-in patch and records its SHA-256 in the
  lockfile resolution;
- all legacy parser calls in issuer discovery, relative callback parsing, end-session generation,
  WebFinger, and the optional Passport strategy use WHATWG `URL`;
- callback allowlisting and query parsing remain unchanged, while end-session default precedence and
  repeated provider query values are preserved;
- `OIDC_ISSUER` accepts only a canonical HTTP(S) URL, apart from one optional trailing slash, and
  rejects credentials, query data, fragments, non-HTTP(S) schemes, backslash spellings, dot-segment
  spellings, and doubled trailing slashes;
- `pnpm oidc:check` validates the patch mapping/hash, scans the exact installed runtime for
  `url.parse()`, verifies Keycloak PKCE/state, and executes loopback discovery plus callback,
  logout, and Passport URL paths;
- the OIDC gate passes with `NODE_OPTIONS=--throw-deprecation`;
- the patch is explicitly a compatibility bridge with stable-upstream removal criteria, not a silent
  framework migration or local OIDC reimplementation.

Existing session-cookie format, provider-token storage, refresh rotation, RP/back-channel logout,
distributed revocation, BFF admission, API verification, tenant authority, and financial behavior do
not change. No migration, reconciliation rule-version update, provider scope, source-system write,
AI authority, autonomous financial action, money, currency, tolerance, match, exception, or approval
behavior changes.
