## Exact completion blockers

The remaining evidence cannot be produced honestly from the current workspace alone:

1. **Current database runtime:** `DATABASE_ADMIN_URL`, `DATABASE_MIGRATION_URL`, `DATABASE_URL`, and
   `DATABASE_WORKER_URL` are absent, and no Docker/PostgreSQL runtime is available. Migrations
   0049–0050 have static/source-defined restricted-role coverage but need fresh and populated live
   execution.
2. **Provider authority:** authorized Shopify and Stripe installations, scopes, sandbox accounts,
   webhook subscriptions, API traffic, and owner-approved provider policies/credentials are absent.
   Synthetic contract tests cannot stand in for provider acceptance.
3. **Protected staging authority:** no target, deployment credentials, owner authorization, approved
   topology, or production-like secret/KMS/backup/collector services are available. The repository
   must not deploy or publish without that authority.
4. **Operational coordination:** no selected collector/backend, notification integration, on-call
   roster, escalation policy, or owner-approved threshold/SLO exists. The source alert policy
   remains intentionally production-disabled.
5. **Business/legal owner decisions:** retention durations, provider repair cadence/capacity, Stripe
   fee-product semantics, merchant/customer privacy transfer, copy disposition, and whole-tenant
   deletion scope require accountable owner/legal/product decisions rather than code guesses.
6. **Representative distributed evidence:** sustained multi-replica load, multi-host partitions,
   managed Redis failure, ingress disconnect, supervisor recovery, and provider capacity need an
   authorized representative environment.
