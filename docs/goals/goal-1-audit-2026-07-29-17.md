the reference Nginx forwarding-overwrite and outer-budget policy, and dependency transport
failure/recovery through two API processes. It did not run the actual production-configured API
limiter through two processes, crash its Redis authority, recover the durable budget, or rotate its
HMAC key. The bounded local composition gap is now materially narrower:

- production startup rejects both a process-local limiter and an unavailable Redis limiter authority
  before opening an API listener;
- two dependency-aware compiled API processes start with `NODE_ENV=production`,
  `NODE_OPTIONS=--throw-deprecation`, one environment, one Redis authority, one HMAC key, and one
  explicit direct-proxy CIDR;
- a bounded loopback proxy removes `Forwarded`, overwrites every `X-Forwarded-*` value, and
  distributes traffic across both processes;
- exactly 120 limited requests are admitted across both processes and request 121 returns the fixed
  correlated 429. One environment-scoped 64-hex HMAC key exists with a positive TTL, while forged
  forwarding prefixes and raw addresses create no alternate key;
- after an explicit Redis snapshot, `SIGKILL` makes both limited requests return the fixed opaque
  500 before authentication or route execution, while both process-only liveness routes remain 200;
- the same authenticated append-only Redis authority restarts. Both processes still reject the
  exhausted budget, while a distinct unaffected address is admitted through both and creates only
  one additional pseudonymous key;
- both old API processes are fully drained before a new shared HMAC key starts two new processes.
  Both processes again share exactly one new 120/121 budget; the old keys remain inaccessible to the
  new key and expire only through their existing bounded TTL; and
- all API, proxy, and Redis listeners close, and the verifier deletes its ephemeral Redis state.

The verifier discards every child-process stream and holds raw client addresses/forwarding headers,
